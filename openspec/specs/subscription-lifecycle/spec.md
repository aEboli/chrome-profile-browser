# subscription-lifecycle Specification

## Purpose
明确在线订阅节点的归属与删除规则，兼容历史记录及重复节点 ID。删除订阅后保留其他订阅和手动节点，并仅清理已无节点记录的环境连接及订阅引用。

## Requirements

### Requirement: 删除订阅必须删除所属节点

删除在线订阅时，应用 MUST 删除该订阅当前归属的所有节点，并从订阅分组、节点列表和环境连接选择器中移除这些节点。

#### Scenario: 删除订阅及其来源节点

- **WHEN** 用户确认删除一个在线订阅
- **THEN** 订阅记录和其 `sourceId` 匹配的节点被持久化删除
- **AND** 引用这些节点的已停止环境切换为系统直连
- **AND** 手动节点与其他在线订阅节点保持不变

#### Scenario: 兼容历史订阅归属

- **WHEN** 旧订阅只在订阅记录的 `nodeIds` 中保存节点归属，节点没有 `sourceId` 或其来源订阅已不存在
- **THEN** 删除该订阅时这些历史节点也被删除
- **AND** 节点明确属于其他仍存在的在线订阅时不得被误删

#### Scenario: 不同节点记录具有相同 ID

- **WHEN** 目标订阅节点与其他订阅或手动节点记录具有相同 ID
- **THEN** 删除时逐条判断节点归属，保留不属于目标订阅的记录
- **AND** 该 ID 仍存在于节点列表时，环境连接引用和其他订阅的 `nodeIds` 保持不变
- **AND** 该 ID 没有剩余节点记录时，环境切回系统直连，并清理其他订阅的失效引用

### Requirement: 订阅节点 ID 必须反映实际存储

订阅刷新成功后，订阅记录的 `nodeIds` MUST 只包含本次实际写入全局节点列表的节点 ID。

#### Scenario: 刷新遇到重复节点

- **WHEN** 刷新结果中的节点因全局去重而未写入
- **THEN** 订阅记录不得保存该未写入节点的悬空 ID

### Requirement: 订阅更新后自动检查节点

应用 MUST 在在线订阅更新成功后自动批量检查本次更新订阅的可检查节点，复用现有节点检查和结果持久化流程。自动检查 MUST 独立于当前搜索及分组筛选，并跳过不支持的节点及订阅信息节点。

#### Scenario: 更新全部订阅

- **WHEN** 用户点击“更新订阅”
- **THEN** 应用按现有订阅顺序完成全部更新
- **AND** 更新结束后统一批量检查成功更新订阅的当前节点
- **AND** 不检查手动节点或已被新订阅结果替换的旧节点

#### Scenario: 更新单个订阅

- **WHEN** 用户点击某个订阅的在线更新按钮且更新成功
- **THEN** 应用自动批量检查该订阅的当前节点
- **AND** 不受当前节点搜索或分组影响
- **AND** 不检查其他订阅节点

#### Scenario: 部分订阅更新失败

- **WHEN** 全部更新中某个订阅更新失败
- **THEN** 应用显示该订阅的更新错误并继续更新后续订阅
- **AND** 自动检查仅包含成功更新订阅的节点

#### Scenario: 没有可自动检查的节点

- **WHEN** 全部订阅更新失败或成功更新的订阅没有受支持的实际节点
- **THEN** 应用不启动空批量检查
- **AND** 更新入口恢复可用

#### Scenario: 更新或检查正在执行

- **WHEN** 订阅更新、自动批量检查或手动批量检查正在执行
- **THEN** 更新入口与手动批量检查入口禁用
- **AND** 重复触发不会产生重叠的更新或批量检查
- **AND** 检查时节点显示检查中，结束后恢复操作入口并显示检查汇总
