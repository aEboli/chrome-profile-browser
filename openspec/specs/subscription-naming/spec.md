# subscription-naming Specification

## Purpose
从可读来源生成订阅名称，过滤访问令牌和信息节点，保留手工名称，并在迁移、刷新和排序后保持账号标识稳定。

## Requirements

### Requirement: 订阅名称必须优先使用可读来源

订阅导入或刷新成功后，应用 MUST 按手工名称、服务端名称、URL 名称提示、节点备注、URL 主机名的顺序选择名称，并过滤访问令牌和元数据提示行。

#### Scenario: 服务端返回订阅名称

- **WHEN** 响应头或 `Content-Disposition` 提供可读名称
- **THEN** 订阅记录使用该名称
- **AND** 刷新时保留该自动来源名称，除非用户手工修改

#### Scenario: 地址没有名称但节点有备注

- **WHEN** 响应没有名称且订阅地址只有通用路径或 token
- **AND** 节点包含可读备注
- **THEN** 订阅记录使用节点备注作为名称

#### Scenario: 访问令牌包含分隔符或 URL 编码

- **WHEN** 名称候选包含 UUID 或含连字符、下划线的不透明令牌，包括 URL 编码和下载文件名中的令牌
- **THEN** 应用在替换显示分隔符前识别并排除令牌
- **AND** 继续回退到可读节点备注或 URL 主机名

#### Scenario: 信息节点具有装饰前缀

- **WHEN** 流量或到期信息节点包含表情等装饰前缀
- **THEN** 命名候选复用订阅信息节点识别，排除整条信息节点及其主机名
- **AND** 没有其他可读节点时使用订阅 URL 主机名

#### Scenario: 名称来源不可用

- **WHEN** 响应、地址和节点都没有可读名称
- **THEN** 订阅记录使用 URL 主机名
- **AND** 无有效 URL 时使用通用默认名称

### Requirement: 订阅必须具有稳定账号标识

每个订阅记录 MUST 持久化唯一的账号标识；历史记录缺失或重复标识时，应用 MUST 分配未占用的标识，并在订阅行、节点分组和连接选择器中显示。

#### Scenario: 多个订阅使用相同名称

- **WHEN** 两个订阅的自动名称或手工名称相同
- **THEN** 界面仍通过不同账号标识区分它们
- **AND** 刷新订阅不得改变已有标识

#### Scenario: 旧订阅缺失标识且排在已有标识之前

- **WHEN** 订阅列表同时包含缺失、重复和有效账号标识
- **THEN** 应用先预留所有有效标识，再为缺失和重复项分配未占用标识
- **AND** 非重复已有标识不因列表顺序或排序调整改变，保存和重新载入后保持一致

### Requirement: 手工改名优先级最高

用户通过订阅编辑或名称快捷编辑保存的名称 MUST 标记为手工名称；后续刷新不得用服务端、URL 或节点名称覆盖该名称。

#### Scenario: 刷新保留用户手工名称

- **WHEN** 用户把订阅名称改为“家庭线路”并随后刷新订阅
- **THEN** 订阅名称仍为“家庭线路”
- **AND** 自动名称来源只更新订阅内容，不覆盖手工名称
