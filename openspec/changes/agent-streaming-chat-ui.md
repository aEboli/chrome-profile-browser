# Agent 流式对话与动作状态展示

## 目的

- 让网页助手以流式方式显示模型文本，减少等待整段回复的空白时间。
- 在模型观察或思考期间显示可感知的加载状态，并在首开对话面板时给出欢迎语。
- 保留自然聊天能力；普通问题直接回答，只有需要页面信息或操作时才调用工具。
- 将网页动作和普通回答拆成不同的视觉组件，动作显示中文名称、执行状态和可展开结果。

## 行为

- 主进程按已配置协议请求流式响应，通过 profile 校验的 IPC 增量事件传递文本；OpenAI Chat Completions、OpenAI Responses、Anthropic Messages 和 Google Gemini 使用各自的流式格式。
- renderer 收到文本增量后立即更新助手气泡；等待页面观察或模型首个文本增量时显示思考动画。
- Agent 欢迎语只在当前浏览器壳首次打开网页助手面板时插入一次，提示用户可以聊天或请求网页帮助。
- 工具调用显示为独立动作卡片，状态区分执行中、已完成、失败和已跳过；工具结果默认折叠并支持复制，不与普通文本气泡混排。
- 对闲聊、解释和一般问题，系统提示要求直接回答而不强制调用浏览器工具。

## 安全边界

- Token、完整请求和远程流仍只在主进程处理；IPC 只发送文本增量和已解析的受限结果。
- 页面工具继续复用已有白名单、当前活动标签校验和串行执行队列。

## 可验证成功标准

1. 流式协议请求包含流式标记，文本增量能在最终响应完成前显示；非流式或不支持流式的响应仍能回退为一次性解析。
2. Agent 等待页面观察或模型响应时，对话框显示动画思考状态，收到首段文本或请求结束后移除。
3. 首次打开网页助手面板显示欢迎语，普通聊天输入不会被改写为工具任务。
4. 工具调用使用独立动作卡片，能显示中文动作名、状态和折叠结果；普通回答仍显示为聊天气泡。
5. `node --test test/*.test.js` 与 Node 语法检查通过。
