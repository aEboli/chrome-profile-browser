## 背景

启动器卡片在环境状态行内显示 `launch-card-engine` 标签。标签位于启动卡片主按钮之外，因此可以改为独立按钮而不嵌套按钮。每环境模式已保存在 profile 的 `engineMode`；环境编辑器会阻止运行中的环境修改该值，外部环境解析共享手动路径或自动发现的 Google Chrome。

## 设计决策

1. 将引擎标签渲染为独立 `<button>`，使用 `data-action="toggle-profile-engine"` 和 profile ID。按钮有描述当前模式及点击后目标模式的 `aria-label` 与 `title`。
2. 点击后在渲染进程计算目标模式并调用专用 `profile:set-engine-mode` IPC。主进程只更新指定 profile 的 `engineMode`，随后广播状态；不把整个 renderer profile 对象写回状态。
3. 主进程拒绝不存在的 profile、无效模式、正在启动/运行/停止的 profile，以及找不到有效手动或自动发现 Chrome 的外部模式请求。
4. 对运行中的 profile，按钮显示当前模式但保持禁用，并通过 title/aria-label 说明需先停止环境。停止后点击立即生效于下一次启动。
5. 成功后刷新状态并显示目标内核；失败时显示错误且保留原按钮状态。切换成功不触发启动、停止或重启。
6. 点击事件由现有 `[data-action]` 委派处理，按钮处于 launch button 外部；事件分支只调用模式更新函数，不调用启动操作。

## 交互

- 已停止环境：引擎标签按钮可聚焦/点击，点击后立即切换并保存。
- 运行中或正在处理的环境：按钮禁用，保留当前模式文字并说明先停止环境。
- 切换到外部模式时：复用设置页中的有效手动 Chrome 路径；路径为空时使用现有自动发现。两者都不可用则提示用户配置 Chrome，当前模式不变。
- 切换成功不打开编辑窗口，不改变新环境默认值，不启动浏览器。

## 风险与处理

- 卡片里的模式标签若继续使用普通 span 会没有明确可点击语义；改成独立按钮并覆盖键盘操作和禁用状态。
- 使用完整 profile 保存 payload 容易意外覆盖其他配置；专用 IPC 只写 `engineMode`。
- 状态可能在卡片渲染后变成运行中；主进程再次校验运行状态，不能依赖 renderer 禁用按钮作为安全边界。
- 自动发现失效或 Chrome 被移动时切换必须失败且原模式不变。

## 验证

- 主进程测试验证只修改目标 profile 的 `engineMode`、外部 Chrome 路径校验、运行中拒绝、无效请求拒绝及失败不改状态。
- renderer 测试验证按钮语义、目标模式、运行状态禁用、点击不触发启动和成功/失败反馈。
- 运行定向测试、完整测试、`npm run check`、`git diff --check` 与 OpenSpec 严格校验。
