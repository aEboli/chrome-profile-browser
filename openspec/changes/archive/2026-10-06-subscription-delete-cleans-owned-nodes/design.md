# 设计

- 在 `subscription-lifecycle` 纯数据模块中集中计算目标订阅的节点 ID：优先使用节点 `sourceId`，再使用目标订阅的 `nodeIds` 识别没有归属或归属已失效的历史节点。
- 如果节点明确属于其他仍存在的订阅，不因目标订阅的旧 `nodeIds` 声明而删除该节点。
- 删除事务按节点记录归属从 `nodes` 移除目标节点，再计算没有剩余记录的节点 ID；仅对这些 ID 将 profile 切回系统直连并清理其他订阅引用，最后移除订阅记录。仍存在同 ID 节点时保留引用。
- 订阅刷新插入节点时收集实际写入的节点 ID，写回订阅记录，避免重复节点被去重后留下不存在的 ID。
- 主进程继续在删除前拒绝正在运行环境使用的目标节点；成功更新后复用现有状态广播刷新节点列表和选择器。
