## Context

密码簿由配置中心 renderer 展示，网页登录提示在 browser shell 中显示。主进程已经按环境、账号和规范化 origin 更新已有记录；本次需要让界面识别并表达该更新行为。

## Decisions

- 使用完整 HTTP(S) origin（含协议和端口）作为网站分组键，与自动保存查重规则保持一致。没有有效地址的旧记录按服务名分组，确保记录仍可访问。
- 使用原生 `details` 和 `summary` 实现可键盘操作的折叠分组；站点行只显示地址和多账号数量，展开后保留现有记录编辑、删除和掩码密码能力。
- 桌面工具栏使用三列布局；窄视口允许环境选择、搜索和添加操作分行，以避免控件挤压。
- 保存提示通过当前环境现有的、仅返回非密码字段的候选查询判断账号是否存在；实际保存仍调用原有按 origin 和账号更新记录的主进程逻辑。
- 候选和保存弹窗继续锚定登录字段，并使用浏览器壳配色；不请求网站 favicon，避免把保存的网站地址发送到外部服务。

## Risks / Trade-offs

- 候选查询失败时提示回退为“保存”；主进程写入仍会按原有查重规则更新已存在记录。
- 多个同源账号搜索时，站点分组只展示当前匹配账号数量，清空搜索后恢复完整数量。

## Migration Plan

无需迁移数据。已有有效地址按 origin 自动分组；没有有效地址的旧记录按服务名分组。展开状态仅保存在当前页面内存中。
