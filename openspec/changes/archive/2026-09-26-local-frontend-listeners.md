# 本地服务面板仅显示前端项目

## 目的

- 避免本地服务面板混入 Windows 系统服务、后端进程等无关 TCP 监听端口，并让用户能按项目名称识别前端入口。

## 规范增量

- 本地服务面板只显示能识别为前端开发服务器、且能解析项目名称的 Windows TCP `LISTENING` 项。
- 监听项关联的进程必须符合已支持的前端开发服务器启动特征；系统服务、后端启动命令、未识别进程以及无法解析项目名称的项不显示。
- 项目名称优先读取项目根目录 `package.json` 的 `name` 字段；该字段缺失时使用项目根目录名。
- 每条列表记录在可点击访问地址右侧显示项目名称，并保留原始监听地址信息。
- 列表计数仅统计实际展示的前端项目监听项；刷新和点击地址的行为保持现有规则。

## 方案设计

- 从 Windows TCP 监听结果保留 PID，并关联本机进程命令行；不向监听端口发送探测请求。
- 通过明确的前端开发服务器命令特征过滤监听进程，首批覆盖 Vite、Next.js、Nuxt、Angular CLI、Vue CLI、Create React App、Astro、SvelteKit、webpack-dev-server、Parcel 和 Rsbuild。
- 从前端启动脚本所在项目定位 `package.json`，以其 `name` 字段作为右侧标签；缺少 `name` 时回退到项目目录名。
- 采用窄名单识别；不能从进程信息可靠判断前端工具或项目目录时不展示该监听项，避免把全部本机监听端口重新列出。
- 复用现有安全的 profile IPC，只向 renderer 返回展示所需的监听地址、端口和项目名称。

## 验收标准

- 后端进程和 Windows 系统服务的监听端口不出现在面板中。
- 常见前端开发服务器的监听端口显示可访问地址及对应项目名。
- 项目名优先使用 `package.json` 的 `name`，缺失时显示项目目录名；无法确定项目目录时不展示该项。
- 面板计数等于列表中可见记录数，刷新、协议选择和当前标签导航继续可用。
