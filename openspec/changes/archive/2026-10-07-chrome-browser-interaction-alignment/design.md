## 现有结构与问题

- 标签状态由 `browser-shell.js` 中的 `tabItems` 管理。`createTab` 的第二个参数是地址栏聚焦，但调用方把它当成后台打开，导致 `focus: false` 也激活新标签。
- 外层 renderer 的键盘事件无法覆盖 `<webview>`；主进程的 `handleGuestShortcut` 目前只转发新建标签和收藏栏切换，并直接执行可配置刷新/开发者工具操作。
- `navigationHistory` 是 renderer 内存数组，最多 30 个地址。现有历史页已经是独立壳页面，应继续复用，不能当作网页 guest。
- 下载 `DownloadItem` 已由主进程按 profile 跟踪，但公开记录没有暂停和恢复能力，renderer 对所有非进行中记录都显示打开文件。
- `findInPage` 已在一次性查找入口使用，但未消费 `found-in-page`，也没有连续查找和关闭清理。

## 命令与状态

- 给标签创建明确的激活、地址栏聚焦和插入位置选项。更新页面链接、收藏、Agent 及菜单调用方，保留既有 IPC 的 `focus` 语义。
- 用固定命令集合统一壳键盘和主进程网页键盘，准确区分 Shift/Alt/Control/Meta，并让已有可配置快捷键优先。网页向壳的转发携带受信任 profile 和 tab 标识，renderer 验证标签仍存在。
- 固定标签只在当前窗口保留，不增加启动恢复。固定区保持在标签序列左侧；复制、恢复、关闭其他/右侧和拖动共用同一顺序，批量操作不会关闭固定项。
- 网站静音作用于当前 profile 窗口内同 hostname 的标签，导航后重新计算；声音标识反映实际播放和静音状态，不通过标题或 URL 猜测。
- 导航与查找状态按标签保存。查找通过鉴权后的主进程调用 Chromium `findInPage`，首次请求使用 `findNext: true`，连续匹配使用 `false`；事件携带 guest ID、请求 ID 和递增 token。切换标签或导航时更新工具栏，拒绝旧页面的异步结果，关闭时取消查找和计时器。

## 历史存储

- 在 profile 中增加规范化历史字段，缺失字段按空数组迁移。只保存 HTTP(S) 的地址、标题和实际访问时间，剔除 URL 中的用户名密码；同地址保留最新访问，最多 1000 条，规则写入规范。
- 主进程仅记录属于该 profile 的网页主框架已提交导航，页面标题更新补充对应记录。读取、删除和清空接口使用既有 sender 到 profile 的鉴权，不允许调用方任意指定 profile。
- 继续使用历史壳页面和地址建议；首次读取不能覆盖读取期间新产生的记录。规范化、去重和删除由纯数据模块复用。
- 浏览数据清理同时清除历史；删除 profile 随记录删除；新标签和其他壳页面不产生浏览历史。

## 下载与界面

- 下载记录同步 `isPaused`、`canResume`、事件状态与最终状态，暂停/继续接口检查任务归属和当前能力。服务器不支持恢复时采用 Electron 给出的结果，不承诺断点续传。
- 只有完成任务可打开文件，中断任务只有在可恢复时提供继续；取消和终止后的按钮状态及时更新。
- 进度、活动数和完成提示都放在现有下载按钮/面板中，不抢焦点，不自动关闭 Agent 或覆盖页面输入。
- 复用项目现有 SVG 图标系统、主题变量和浮层/确认框，菜单采用可键盘操作的现有或 Electron 原生菜单。稳定控件尺寸与预留空间防止状态变化造成位移。
- 保持现有网页主色标签和背景设置；以紧凑工具栏、清晰活动标签、准确悬停与焦点反馈对齐 Chrome 的操作节奏。
