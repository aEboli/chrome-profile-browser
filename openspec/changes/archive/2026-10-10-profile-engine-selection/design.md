## 背景

`settings.engineMode` 当前同时是设置页选择值和所有环境的启动分支。启动器卡片直接启动 profile，因此没有逐环境选择引擎的入口。外部可执行文件路径已独立保存在全局设置中，外部启动会使用按环境隔离的数据目录。

## 设计决策

1. 环境记录新增规范化字段 `engineMode`，只接受 `electron` 或 `external`。`settings.engineMode` 保留为新建环境的默认模式，不再决定已有环境的启动分支。
2. 状态加载时，缺少 `engineMode` 的旧环境继承规范化后的全局默认模式；新建环境也以当前全局默认模式初始化。之后每个环境都保存明确值，不使用运行时动态继承。
3. 环境编辑窗口提供互斥的内置/外部选择。设置页继续管理共享的外部 Chromium 可执行文件和新环境默认值，并明确说明更改默认值不会改动现有环境。
4. 保存外部模式的环境前验证共享 `enginePath` 指向有效可执行文件；启动时仍重新验证，以覆盖文件被移动或删除的情况。内置模式不依赖该路径。
5. `launchProfileInternal()` 根据 profile 的 `engineMode` 选择现有 Electron 或外部启动流程。代理、扩展和数据目录仍按现有实现处理；两个模式可同时运行。
6. 将 profile 的 `engineMode` 纳入 `profileSaveConfig()`，由现有运行中环境配置保护拒绝热切换。全局外部路径的既有运行限制保持不变。
7. 启动器卡片显示已保存的引擎类型，便于启动前区分各环境。
8. 安装浏览器内核后仍将全局默认模式设为 `external`；已有 profile 的模式不被安装操作覆盖。

## 交互

- 新建环境时，编辑器选择器初始值来自当前全局默认引擎。
- 编辑现有环境时，选择器显示该环境已保存的引擎模式。
- 选择外部 Chromium 但没有有效共享可执行文件时，保存失败并提示先在设置页配置浏览器路径。
- 启动器卡片分别显示“内置 Chromium”或“外部 Chromium”。
- 运行中的环境不可更改引擎模式；停止后可修改并对下次启动生效。

## 风险与处理

- 旧环境迁移必须参考同一状态文件中的全局模式，避免旧外部环境在新版本中切到 Electron。
- 任何启动分支残留对全局 `settings.engineMode` 的依赖，都会覆盖环境自己的选择；测试需检查 profile 模式驱动启动分支。
- 修改全局默认值不得重写已有 profile；新增环境应仍继承默认值。
- 外部可执行文件仍是共享配置。路径失效时仅外部模式的 profile 受影响，内置模式继续可启动。

## 验证

- Store 测试验证旧环境迁移、显式模式保留及不同 profile 模式并存。
- 主进程回归验证按 profile 模式启动、外部路径校验、运行中拒绝改模式和安装行为不覆盖 profile 选择。
- 渲染回归验证环境选择器的初始化和保存，以及启动器卡片模式标识。
- 运行定向测试、`npm test`、`npm run check`、`git diff --check` 和 OpenSpec 严格校验。
