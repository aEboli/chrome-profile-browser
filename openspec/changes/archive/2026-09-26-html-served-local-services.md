# 识别由本地服务托管的前端页面

## 目的

- 让本地服务面板也能发现由后端可执行程序托管、但实际提供网页界面的本地服务，例如 `localhost:8080` 上的 Sub2API 管理页面。

## 规范增量

- 在已有前端开发服务器命令识别之外，面板可检查 Windows TCP 监听地址的根路径响应；仅将成功返回 HTML 页面的服务作为前端入口展示。
- HTTP/HTTPS 请求只连接 netstat 返回的本机监听地址，不跟随重定向，也不访问外部域名；探测必须有超时、并发和响应读取限制。
- 后端进程若根路径返回 HTML 页面则作为包含前端界面的服务入口显示；只返回 JSON、文本、协议数据或错误响应的后端端口不显示。
- 页面项目名优先使用项目 `package.json` 的 `name`；没有项目清单时使用可执行文件所在目录名，无法得到目录名时使用进程名。
- 原有项目名、右侧标签、同项目同端口多地址合并和可见数量规则保持一致。

## 方案设计

- 保留已有的前端开发服务器命令识别作为快速路径；未识别的监听项才执行本机 HTTP/HTTPS 根路径检查。
- 页面响应需为成功状态并声明 `text/html`；探测停止在响应头或有限 HTML 片段处，不读取完整页面，不执行页面脚本，不跟随 30x 跳转。
- 仅使用扫描得到的本机绑定地址，通配地址映射到回环地址；每个协议请求设置短超时，并限制同时探测的端口数，避免刷新长时间阻塞。
- 进程查询增加可执行文件路径和进程名；非 Node 项目名称由可执行文件目录提供，Node 项目继续优先读取 `package.json`。

## 验收标准

- `localhost:8080` 这类根路径返回 `200 text/html` 的本地页面显示在面板中。
- 仅返回 JSON 的后端 API 和不支持 HTTP/HTTPS 的监听项不显示。
- 探测不跟随重定向、不访问本机之外的地址；慢响应在限定时间后放弃，面板刷新可完成。
- HTML 服务右侧显示项目名；没有 `package.json` 时能使用可执行文件目录名。
