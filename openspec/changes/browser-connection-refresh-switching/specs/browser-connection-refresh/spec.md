## Purpose

为浏览器壳提供按当前连接模式重新检测的入口，使用户可以更新连接状态和延迟，并在订阅自动模式下立即选择并热切到该订阅内最低延迟的可用线路。

## ADDED Requirements

### Requirement: 浏览器连接信息按当前模式重新检测

浏览器右上角连接信息 MUST 提供手动重新检测操作，并按 profile 当前连接模式执行。检测期间 MUST 防止重复提交并向用户显示处理中状态；检测完成后 MUST 更新连接信息并报告结果。

#### Scenario: 重新检测指定节点

- **WHEN** 用户在指定节点模式下点击浏览器右上角连接信息
- **THEN** 应用仅检查当前指定节点并更新其状态、延迟及可用出口信息
- **AND** 应用不切换节点、不重启浏览器或刷新当前页面

#### Scenario: 重新检测系统直连

- **WHEN** 用户在系统直连模式下点击浏览器右上角连接信息
- **THEN** 应用重新检查系统直连并更新显示的状态、延迟及出口信息
- **AND** 检查失败时浏览器壳显示失败结果

#### Scenario: 检测期间重复点击

- **WHEN** 当前 profile 的连接重新检测仍在进行
- **THEN** 浏览器壳将检测入口标为处理中并禁止重复触发
- **AND** 应用不并行执行该 profile 的另一项连接切换操作

### Requirement: 重新检测订阅并热切到最低延迟线路

订阅自动模式下的手动重新检测 MUST 仅检查当前订阅中受支持的节点，并从本轮检查成功的节点中按延迟和订阅顺序稳定选出最佳线路。若最佳线路不同于当前线路，应用 MUST 更新当前 profile 的订阅路由而不重启浏览器或刷新页面；若最佳线路与当前相同，应用 MUST 保持现有路由。没有可用线路时 MUST 保留订阅模式及现有路由，并报告无可用线路；MUST NOT 回退到其他订阅、指定节点或直连。

#### Scenario: 当前订阅中出现更低延迟线路

- **WHEN** 用户在订阅自动模式点击连接信息，且所选订阅有延迟更低的可用线路
- **THEN** 应用将新建连接热切至该线路，并更新当前节点、延迟、国家及出口 IP 信息
- **AND** 浏览器进程、窗口和当前页面文档保持不变
- **AND** 界面告知用户线路已切换且出口 IP 可能变化

#### Scenario: 当前线路仍是最佳可用线路

- **WHEN** 用户重新检测订阅，且当前线路仍是本轮最低延迟的可用线路
- **THEN** 应用更新当前线路的检测信息并保留原路由
- **AND** 浏览器进程、窗口及当前页面文档保持不变

#### Scenario: 最快线路无法启动

- **WHEN** 本轮最快节点通过连通性检查，但代理线路启动失败
- **THEN** 应用按延迟顺序尝试同一订阅中的后续可用节点
- **AND** 成功时热切到首个可启动的节点
- **AND** 全部候选启动失败时保留原路由并显示错误结果

#### Scenario: 所选订阅没有可用线路

- **WHEN** 用户重新检测订阅且该订阅中没有检查成功的受支持节点
- **THEN** 环境保留当前订阅自动模式和原路由
- **AND** 浏览器壳显示该订阅暂无可用线路
- **AND** 应用不改用其他订阅、指定节点或直连

### Requirement: 手动线路菜单展示节点出口信息

手动线路菜单中的代理节点 MUST 依次显示出口 IP 地址、国家/来源/属性和最近一次延迟或检查状态。国家、来源和属性 MUST 使用分段留白和相近的低饱和颜色，未分类组合保持次级文字色；来源和属性 MUST 去掉末尾的“IP”，尚未查询的字段 MUST 显示“未查询”，且 MUST NOT 从节点名称推断。原节点名、协议和服务器地址 MUST 保留在候选项的无障碍名称和悬浮提示中，展示调整 MUST NOT 改变节点选择标识或切换行为。

#### Scenario: 查看订阅或手动节点

- **WHEN** 用户打开右键手动线路菜单
- **THEN** 每个节点候选依次显示 IP 地址、国家·来源·属性、延迟或检查状态
- **AND** 未查询的来源或属性显示为“未查询”，已查询的“原生IP”“住宅IP”“机房IP”分别显示为“原生”“住宅”“机房”
- **AND** 屏幕阅读器和悬浮提示仍可获知节点名、协议与服务器地址
- **AND** 点击候选仍使用原节点 ID 执行线路切换
