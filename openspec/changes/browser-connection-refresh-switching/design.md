# 浏览器连接信息重新检测与订阅热切换

## 背景

浏览器壳右上角已显示当前连接延迟、国家和出口 IP，但这些信息不能主动触发更新。配置中心已有节点连通性检查、订阅节点并发测速、最低延迟排序，以及使用稳定本机代理入口进行订阅热切换的能力。

## 设计决策

1. 将右上角连接信息作为一个明确的按钮，主进程只从已授权的浏览器壳 IPC sender 获取 profile ID，不接受 renderer 传入的 profile 或节点标识。
2. 右键菜单由主进程按当前 profile 生成，分组显示系统直连、每个订阅的订阅自动和节点、手动节点；只返回名称、地址、协议、状态和延迟等脱敏信息。
3. 选择固定节点或系统直连时复用现有 profile 切换逻辑。运行中的环境在停止前完成目标线路检查和出口 IP 变化确认，确认后再重启到目标线路；取消或检查失败时保留当前环境。
4. 指定节点模式只调用当前节点检查，复用节点已有状态与延迟结果，不改变 profile 连接、不重启浏览器。
5. 订阅自动模式重新检查所选订阅内全部受支持节点，沿用最多 10 路并发和稳定排序。若当前线路仍是最低延迟可用线路，则保持原路由；否则按测速排序尝试切到首个成功启动的节点，并复用现有 profile 转发器，不停止浏览器、不刷新页面。
6. 订阅没有可用节点时保留订阅模式和原路由，向浏览器壳报告无可用线路；不切到其他订阅、手动节点或直连。
7. 直连模式复用直连检测。按钮在检测或手动切换时禁用，同一 profile 的重复请求合并；检测期间拒绝启动会改写线路的手动切换或自动故障切换。
8. 检查结果通过现有连接信息更新事件刷新延迟、国家和 IP。浏览器壳在状态栏反馈成功、失败、无可用线路、手动切换和热切结果；热切时说明出口 IP 可能变化。

## 风险与边界

- 重新检测订阅中的所有受支持节点可能需要数秒，单节点检查仍使用既有限时和错误处理。
- 只有订阅自动模式能从订阅候选中择优切线；指定节点和直连检查失败时只反馈结果。
- 热切切换后新建连接使用新线路，已有连接仍按现有转发器行为保留。

## 验证

- 检查 renderer、preload 和 main 的 JavaScript 语法及 `npm run check`。
- 运行 OpenSpec 严格校验，确认新增行为规范与实现范围一致。
- 手动复核点击入口、模式分流、重测状态、无可用线路反馈和不重启/不刷新页面的热切路径；本次不启动真实代理节点进行故障注入。
