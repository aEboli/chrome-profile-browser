# 连接状态与延时监测

## 目的

在环境列表的“连接”列显示所选连接的当前状态和最近一次检测延时，并由主进程在应用运行期间每 60 秒自动检测一次。

## 行为

- 应用启动后立即检测当前环境实际选中的 HTTP、HTTPS、SOCKS5 和核心托管节点；之后每 60 秒检测一次。未被环境使用的节点仍可手动检查。
- HTTP、HTTPS 和 SOCKS5 节点测量代理握手延时；VMess、VLESS、Trojan、Shadowsocks 和 AnyTLS 等核心托管节点启动一次隔离的临时核心，并通过本地 SOCKS5 完成真实代理握手后才显示可达，延时从核心启动开始计至目标握手完成。
- 检测成功显示“已连接”和毫秒延时；检测失败显示失败状态并清除本次延时；尚未检测时显示“未检测”。
- 直连环境使用系统默认网络路径检测公共 HTTP 目标，结果只在当前应用会话中保存。
- 节点的最近检测时间、状态、阶段、错误和成功延时保存在本地状态文件，并通过现有状态推送更新界面。

## 设计与验证

- 复用现有 `proxy-check` TCP/代理握手实现；核心节点检查通过注入的临时核心生命周期回调完成真实 SOCKS5 探测，并保留核心启动到目标握手完成的完整耗时，手动检查和定时检查共用去重的主进程检查任务。
- 为核心节点、失败结果和延时持久化增加自动化测试；运行 `npm test` 与 `npm run check` 验证解析、检查和语法。
- 通过界面检查环境列表的连接选择器下方同时出现状态与 `ms` 延时，等待 60 秒确认状态自动刷新。
