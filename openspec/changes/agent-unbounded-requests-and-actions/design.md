# 设计

- 所有 Agent/JEV 请求继续在主进程发出。每个可取消请求使用唯一 request ID，主进程按 IPC 发送方和 request ID 关联 `AbortController`，阻止一个窗口取消另一个窗口的请求。
- 使用同一取消通道覆盖配置中心和浏览器壳的模型列表、连通性检查、非流式聊天、流式聊天和 JEV 请求；请求完成后移除监听并清理关联表。
- 移除请求/响应字节检查与固定请求定时器。SSE 和普通响应继续按对应协议解析，用户停止和 sender 销毁仍会 abort fetch/stream。
- 动作规范化只校验有限坐标/滚动值、非负等待、非空动作批次、拖拽至少两个点、文本和选择器类型，以及动作和按键白名单；坐标执行时仍必须落在当前可视区域。
- 所有动作仍进入当前 profile 的串行执行队列。队列中的长等待、点击序列、拖拽和批次逐项检查当前任务的取消信号。
- 页面动作参数继续以 JSON 数据传给固定操作模板；不执行模型提供的脚本。取消 JSON transport 的固定长度拒绝，使长文本/批次不被应用层截断或拒绝。
