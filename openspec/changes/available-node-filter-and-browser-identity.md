# 可用节点排序、环境筛选与浏览器连接信息

## 目的

让节点管理和环境连接选择反映最近一次连通性检查结果，并简化浏览器窗口左上角的连接信息，避免把节点名称或代理地址作为主要身份信息展示。

## 行为

- 节点管理页在“全部”及订阅分组中稳定排序：最近检查成功的节点（状态为 `ok`、`ready`、`available`、`healthy` 或 `reachable`）显示在上方，其余节点显示在下方；同一状态组内保持现有顺序。
- 节点管理页仍可查看不可用节点及其状态，便于重新检查或删除；订阅提示型信息节点继续排除。
- 环境连接选择器只把最近检查成功的节点作为候选，未检查、检查中、失败、不支持和无效节点不出现在候选列表；“系统直连”继续作为独立候选。
- 已有环境如果仍指向后来变为不可用的节点，不自动改写或删除该配置；当前连接可继续显示其状态，但不可用节点不会作为新的可选候选。
- 浏览器窗口左上角只保留环境名称、国家和 IP 信息，不显示节点名称、协议、服务器地址或端口。
- IP 默认隐藏实际地址；点击 IP 信息在隐藏和显示之间切换。主进程推送新的国家/IP 信息时保留当前显隐状态，并同步无障碍名称与提示。

## 设计

- 在渲染层集中使用同一组“可用状态”判断，避免节点表和环境选择器出现不同口径。
- 排序使用稳定的可用性分区，不改变节点持久化顺序或节点 ID。
- 浏览器壳继续接收主进程的国家/IP 更新；连接类型字段和对应布局移除，IP 控件使用按钮语义而不是把地址作为静态文本。

## 验证

- 使用包含成功、失败、未检查和不支持节点的状态数据检查：节点表成功节点在上，其他节点在下；订阅信息节点不出现。
- 展开环境连接选择器并打开环境编辑表单，确认候选只包含成功节点和系统直连；已有失效连接不会被刷新或保存操作静默清除。
- 打开浏览器环境，确认左上角只出现环境名称、国家和 IP；首次显示为隐藏值，点击 IP 后显示实际地址，再次点击恢复隐藏；状态推送后显隐状态不变。
- 运行 `npm test`、`npm run check`。
