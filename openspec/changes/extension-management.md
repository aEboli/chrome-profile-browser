# 插件管理与环境激活

## 目的

- 在工作台增加独立的插件管理入口，维护本机安装的 Chromium 扩展。
- 允许为每个浏览器环境单独选择扩展激活范围，并在环境启动时加载到对应的持久化 session。
- 在浏览器工具栏提供同一份扩展清单的启用/停用控制，状态通过主进程广播回工作台。
- 优先读取扩展 manifest 的 HTTPS `update_url`；若 manifest 含可验证公钥，则按 Chrome 扩展 ID 回退到 Google Web Store 官方更新端点，自动检查官方更新清单；用户确认后下载并替换到最新版本。
- 插件管理页始终提供更新操作：本地目录重新读取并应用目录中的代码，有官方来源时下载并替换在线版本。

## 约束

- 插件文件只保存在本机；管理器保存路径和 manifest 元数据，不上传扩展内容。
- Electron 只支持加载解压后的扩展目录；未打包文件夹直接从原路径加载，用户触发本地更新后重新读取并重载代码；外部 Chromium 仍需重启环境后生效；导入 `.zip`/`.crx` 时先在应用数据目录解包并校验 `manifest.json`。
- 仅接受 Manifest V2/V3，插件加载失败不能阻止浏览器环境启动，必须在管理界面和浏览器菜单中显示错误。
- 外部 Chromium 仅在启动参数中加载已激活插件；运行中的外部进程不承诺动态启停，重新启动环境后生效。更新或卸载时会保留其正在使用的旧解包副本，进程退出后再清理。
- 更新检查只接受 HTTPS、限制重定向和下载大小；Google Web Store 回退只使用由公钥计算出的扩展 ID；检查可以自动运行，但安装最新版必须由用户明确触发。

## 验收标准

1. 左侧导航有“插件管理”，可以直接加载未打包插件文件夹，或导入 ZIP/CRX，并显示名称、版本、来源模式和路径。
2. 每个插件可以按浏览器环境分别勾选激活范围；例如插件 A/C 可只分配给浏览器 1，插件 B/C 可只分配给浏览器 2，插件 A/B/C 可分配给浏览器 3。启动环境后扩展只在该环境 session 中加载，修改一个环境不会覆盖其他环境的选择。
3. 浏览器工具栏可以查看当前环境的插件并启用/停用；操作后管理页状态自动同步。
4. 删除插件会从正在运行的 Electron 环境卸载，并清理由应用解包的副本；用户原始目录不被删除。
5. `npm test`、`npm run check` 通过，非法 manifest、路径和压缩包被明确拒绝。
6. 有效 `update_url` 或可验证的 Chrome Web Store 公钥能返回可更新状态，确认后可下载官方 CRX/ZIP 并替换插件；无更新地址或网络失败显示明确状态。
7. 每个插件都显示更新按钮；无在线来源时重新读取本地目录并让运行中的 Electron 环境重载代码，有在线来源时更新官方在线版本，并在外部 Chromium 需要重启时显示提示。
