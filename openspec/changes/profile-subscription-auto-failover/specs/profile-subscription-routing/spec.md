## ADDED Requirements

### Requirement: 浏览器环境支持订阅自动连接模式

环境 MUST 支持系统直连、单节点指定和订阅自动三种并存的连接模式。订阅自动模式 MUST 保存用户选择的本机订阅 ID，并只从该订阅所属且受支持的节点中选择实际线路。选择订阅自动模式 MUST NOT 删除或覆盖现有系统直连和单节点选项；用户选择一个具体节点时 MUST 使用该节点作为固定线路。

#### Scenario: 从环境配置中选择订阅自动

- **WHEN** 用户新建或编辑环境并选择一个已导入订阅的“订阅自动”选项
- **THEN** 环境保存为订阅自动模式并保留该订阅 ID
- **AND** 该模式的实际线路来自所选订阅
- **AND** 既有直连与单节点选择仍可单独使用

#### Scenario: 从环境连接选择器选择订阅

- **WHEN** 用户在环境连接选择器中选择某订阅的“自动选择此订阅”
- **THEN** 应用检查该订阅中受支持的节点并选择检查成功且延迟最低的节点
- **AND** 同延迟时使用订阅中原有顺序靠前的节点
- **AND** 该订阅内原有的逐节点选项仍可用于切回固定单节点模式

### Requirement: 订阅自动选路不得越出用户选择的订阅

应用 MUST 将订阅自动选路限制在 `subscriptionId` 对应的受支持节点中，并 MUST 使用最多 10 路并发的连通性检查选择最低延迟线路。没有可用线路时，应用 MUST 保留订阅自动模式并清楚报告；MUST NOT 静默改用其他订阅、单节点或系统直连。该并发上限只用于订阅自动择优及故障切换，不改变普通批量检查与周期健康检查的既有并发上限。

#### Scenario: 所选订阅有可用线路

- **WHEN** 所选订阅中至少有一个受支持节点通过连通性检查
- **THEN** 应用选择通过检查且延迟最低的节点作为实际线路
- **AND** 检查结果相同时使用订阅节点顺序作为稳定排序

#### Scenario: 所选订阅没有可用线路

- **WHEN** 所选订阅中的受支持节点均检查失败、为空或正在导入
- **THEN** 环境保留订阅自动选择
- **AND** 页面显示该订阅暂无可用线路
- **AND** 环境不得以系统直连或其他节点启动

### Requirement: 当前订阅节点故障时自动切换

运行中的订阅自动环境 MUST 在现有节点连通性检查确认当前实际节点不可达后，检查同一订阅的其他受支持节点，并切至可用节点中延迟最低者。自动切换 MUST 保留订阅自动模式和订阅 ID；MUST NOT 根据 IP 信誉评分触发切换。一个环境同时最多有一个自动切换流程。

#### Scenario: 同一订阅有可用备用节点

- **WHEN** 当前实际线路检查失败且同一订阅有其他检查成功的节点
- **THEN** 环境通过本机转发器将新连接切到该订阅中延迟最低的可用节点
- **AND** 内置 Electron 和外部 Chromium 的进程、窗口、标签及当前页面文档保持不变
- **AND** 已有连接不被应用主动断开，核心线路的旧核心保留到引用它的连接关闭
- **AND** 环境仍显示为订阅自动模式，并更新当前实际节点和延迟
- **AND** 前端告知用户已切线及出口 IP 可能变化

#### Scenario: 故障切线期间保持当前页面

- **WHEN** 运行中的订阅自动环境成功切换到备用线路
- **THEN** 当前标签不导航、不刷新，页面文档和表单状态保持不变
- **AND** 浏览器进程与窗口保持运行，新建网络连接使用备用线路

#### Scenario: 当前线路故障且没有可用备用节点

- **WHEN** 当前线路检查失败且同一订阅的其他节点均不可用
- **THEN** 环境继续保留订阅自动模式和故障状态
- **AND** 前端显示暂无可用备用线路
- **AND** 应用不得改用直连、其他订阅或单节点

#### Scenario: 故障线路恢复

- **WHEN** 当前运行周期内先前故障的线路恢复
- **THEN** 应用不因线路恢复或延迟变化而自动切回
- **AND** 下一次用户重新选择该订阅或启动环境时可重新按当前延迟择优

### Requirement: 前端必须区分订阅自动与固定连接

环境配置、启动器和环境列表 MUST 清楚区分系统直连、单节点指定和订阅自动。订阅自动环境 MUST 显示订阅名称和当前实际节点；正在检查、切换中和没有可用线路等状态 MUST 有明确文案。

#### Scenario: 显示订阅自动环境

- **WHEN** 环境处于订阅自动模式
- **THEN** 前端显示“订阅自动”及订阅名称
- **AND** 有实际线路时显示节点名称和最近连通性/延迟
- **AND** 没有实际线路时显示无可用线路状态而不是“系统直连”

#### Scenario: 保持现有固定节点体验

- **WHEN** 环境处于单节点指定模式
- **THEN** 前端明确显示该环境使用固定节点
- **AND** 连接选择器仍允许选取系统直连或任一可用单节点

### Requirement: 订阅自动模式不要求出口 IP 变化二次确认

订阅自动模式的启动和自动切线 MUST NOT 因出口 IP 与上次成功启动时不同而阻止流程并要求用户再次确认。直连和固定节点模式 MUST 保持原有的出口 IP 变化二次确认行为。

#### Scenario: 启动订阅自动环境时出口 IP 已变化

- **WHEN** 用户启动订阅自动环境，当前所选订阅的最佳可用线路出口 IP 与上次启动记录不同
- **THEN** 环境直接使用订阅内最佳可用线路继续启动
- **AND** 应用更新本次成功启动的出口 IP 记录
- **AND** 应用不显示阻塞式二次确认

#### Scenario: 启动固定连接环境时出口 IP 已变化

- **WHEN** 用户启动系统直连或固定节点环境，出口 IP 与上次成功启动记录不同
- **THEN** 应用仍显示现有出口 IP 变化二次确认

### Requirement: 订阅生命周期变更必须维护自动模式引用

订阅成功刷新并替换节点后，环境 MUST 保留订阅自动模式，并在新节点检查完成后重新确定实际线路。用户删除订阅时，环境 MUST 清理失效的订阅 ID，并按现有订阅删除规则切回系统直连。

#### Scenario: 刷新移除了当前实际节点

- **WHEN** 成功刷新所选订阅并移除环境当前实际节点
- **THEN** 环境继续绑定原订阅自动模式
- **AND** 应用从刷新后的节点中重新选择可用线路
- **AND** 没有可用线路时显示故障状态且不回退直连

#### Scenario: 用户删除所选订阅

- **WHEN** 用户删除环境当前选择的订阅
- **THEN** 环境清除该订阅自动引用并切回系统直连
- **AND** 不影响其他订阅或手动节点
