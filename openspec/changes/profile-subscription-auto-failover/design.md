## Context

profile 当前持久化 `connectionMode: direct | node` 和 `nodeId`。环境连接选择器按订阅分组展示单个节点，但点击节点后只保存该 `nodeId`。主进程现有连接监视器启动时和每 60 秒检查环境实际引用的节点；普通切线会停止并重新启动 profile。订阅刷新可能替换节点，删除订阅会清理该订阅节点及环境引用。

## Decisions

1. 增加 `connectionMode: subscription` 与 `subscriptionId`。`nodeId` 在该模式下表示当前实际线路；尚无可用线路时允许为空。旧数据继续按当前规则解释为 `direct` 或 `node`，不批量改写现有 profile。
2. 订阅自动模式只查询 `sourceId` 属于所选订阅的受支持节点，排除订阅信息行和不支持节点。选路以最多 10 路并发检查候选线路，以本轮检查成功且延迟最低的节点为首选，延迟相同时保持原订阅顺序。通用批量检查和周期健康检查仍保留 3 路并发上限。
3. 用户从连接选择器切换到订阅自动模式时，先检查候选节点再提交连接选择；如果没有可用节点，保留 profile 原连接并明确报告结果。环境配置保存订阅选择后，首次启动仍执行当前订阅线路检查和择优。
4. 启动订阅自动 profile 时重新检查所选订阅的候选节点并选择最佳可用线路。检查失败时不以直连启动；profile 保留订阅自动模式，错误信息说明该订阅没有可用线路。
5. 现有 60 秒监视器继续检查运行中 profile 的实际 `nodeId`。当前节点被现有检查标为不可达后，对同一订阅的其他节点执行有界并发检查，选择延迟最低的可用备用节点；每个 profile 同时只允许一个自动切换流程。执行前再次确认 profile 仍处于订阅自动模式且当前 `nodeId` 未被用户改动，避免竞态覆盖手动操作。
6. 订阅自动环境启动时，内置 Electron 和外部 Chromium 都连接到仅监听 `127.0.0.1` 的本机 HTTP 转发器。转发器按请求读取当前上游线路；自动切换只更新转发器路由和 profile 的 `nodeId`，不停止浏览器进程、不销毁窗口、不关闭标签或刷新当前页面。新连接使用新线路，已有连接继续由其原上游承载；核心线路保留旧核心，直到引用它的转发器连接关闭后再清理。若无备用线路则保持原订阅关联和故障状态，不回退直连；在后续健康检查周期可再次尝试。
7. 订阅自动模式启动和运行中故障切线均不触发出口 IP 确认弹窗，因为用户选择该模式已授权在所选订阅内择优和换线。直连及固定节点启动仍执行现有出口 IP 确认规则。界面即时提示切换结果、出口线路及可能的 IP 变化。
8. 成功刷新订阅并移除当前实际节点时，profile 保留订阅自动模式；刷新后的节点检查完成后重新选路。删除订阅时清除 `subscriptionId` 并按现有生命周期规则将相关 profile 切回系统直连。
9. 前端在环境表单中为每个订阅提供“订阅自动 · 名称”选项；在环境连接选择器的对应订阅分组顶部提供“自动选择此订阅”，该组内原有单节点行继续可用。订阅自动模式的连接摘要显示模式徽标、订阅名称和实际节点，单节点模式仍明确显示“指定节点”。

## Risks / Trade-offs

- 订阅含有大量节点时，初次检查和故障切换仍受 7 秒单节点超时影响；选路最多 10 路并发，并发中的核心节点会各自启动临时核心，因此继续提高并发可能增加 CPU/内存压力。
- 自动切线不迁移已建立的 TCP/HTTPS 隧道；它们仍使用原线路，若原线路已失效，对应请求可能失败。页面文档和浏览器界面保持原样，后续新连接使用备用线路。
- 本机转发器仅绑定回环地址且使用临时端口；其生命周期与 profile 绑定，停止环境或应用退出时关闭。
- 现有 60 秒检查周期决定了后台故障发现的最坏等待时间；网页自身报错但代理节点探测仍成功时不会据此自动换线，避免把单站点故障误判为代理线路故障。
- 自动切换时出口 IP 可能变化。UI 必须在启用模式时说明这一点，并在每次切线后展示当前节点和出口 IP 状态。
- 自动切换与手动切线、订阅刷新、订阅删除可能并发；实施时需按 profile 锁定/去重，并在提交前校验订阅和当前线路仍匹配。

## Validation

- 单元验证：同一订阅中只选可用且延迟最低的受支持节点；平延迟时稳定按订阅顺序；不得跨订阅或回退直连。
- 失败验证：当前线路检查失败时只切至同订阅可用节点；无备用节点时保留订阅模式并报告；同一 profile 的重复失败不并行切换。
- 热切验证：内置 Electron 与外部 Chromium 共用稳定的本机代理入口；切换后同一入口的新请求使用新线路，已建立隧道保持存活；自动切线不调用停止环境、启动环境或页面刷新路径。
- 生命周期验证：订阅刷新替换当前节点后仍留在订阅模式；删除订阅按现有清理规则切回直连；旧 direct/node profile 行为不变。
- 界面验证：环境新建/编辑、启动器和环境列表均能看出指定节点与订阅自动模式差别，并显示实际线路及无线路状态。
- 自动化验证：`npm test` 全量通过，`npm run check` 通过，OpenSpec 严格校验通过。
- 并发验证：自动选路调用独立的 10 路并发上限，通用检查仍为 3 路；批处理器测试确认同时运行数不会超过 10。
- 启动确认验证：订阅模式遇到出口 IP 变化不要求二次确认；直连和固定节点模式仍要求确认。
- 运行验证限制：真实 HTTP/SOCKS5/核心节点的 Electron 与外部 Chromium 故障注入未执行。尝试启动隔离 Electron 和本地模拟代理时被自动审查阻止；没有使用真实用户数据。
